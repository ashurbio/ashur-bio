# بوابة قسم علوم الحياة — الكود المصدري

تطبيق ويب للقسم: جدول، إعلانات، امتحانات، محاضرات، غيابات، ولوحة للممثل.
الواجهة React (Vite)، والسيرفر وقاعدة البيانات على Supabase، والإيميلات عن طريق Brevo.

## محتويات المجلد

| المسار | شنو بيه |
|---|---|
| `web/` | كود الواجهة (الصفحات، التصميم، تسجيل الدخول) |
| `web/src/sb/config.js` | رابط مشروع Supabase والمفتاح العام (مسموح يكون علني، الحماية بقواعد RLS) |
| `web/src/sb/client.js` | الاتصال بالسيرفر وحفظ تسجيل الدخول |
| `web/src/sb/screens.jsx` | شاشات الطالب |
| `web/src/sb/admin.jsx` | لوحة الممثل |
| `supabase/functions/register` | إنشاء حساب ودز اسم المستخدم والرمز بالإيميل |
| `supabase/functions/reset-pin` | «نسيت الرمز» |
| `supabase/functions/mail-status` | فحص إعدادات الإيميل (يشتغل بس بمفتاح الاختبار) |
| `supabase/functions/study-ai` | «المترجم والملخّص»: يترجم أو يلخّص جزء من الملزمة عن طريق Gemini (`gemini.ts` يحتوي طلب Gemini وقراءة الأخطاء) |
| `web/src/sb/study/` | واجهة «المترجم والملخّص»: قراءة الملفات، تقسيمها، والنتائج والأسئلة |
| `supabase/functions/_shared/common.ts` | دوال مشتركة: نص الإيميل، الإرسال، الحد من المحاولات |
| `supabase/schema.sql` | قاعدة البيانات كاملة: الجداول، قواعد الأمان، الصلاحيات |

**ما بيه أي مفتاح سري.** مفتاح Brevo ورمز القسم محفوظين داخل قاعدة البيانات فقط.

## تشغيله على جهازك

يحتاج Node.js 18 أو أحدث.

```bash
cd web
npm install
npm run dev      # يفتح نسخة تجريبية على localhost
npm run build    # يطلع الموقع الجاهز بمجلد dist
```

## فحص التطبيق قبل النشر

مجلد `.claude/qa` بيه فحوصات تلقائية (Playwright) تشغّل كل الشاشات على سيرفر وهمي، وتفحص سهولة الاستخدام (axe) والسرعة (Lighthouse).
طريقة التشغيل مكتوبة بـ `.claude/qa/README.md`. ومجلد `.claude/skills` بيه مهارات Claude الخاصة بالتصميم والفحص والسرعة.

## تحديث الموقع المنشور (GitHub Pages)

1. `npm run build` داخل `web`.
2. انسخ محتويات `web/dist` إلى مستودع الموقع (تحذف مجلد `assets` القديم أول).
3. commit و push على فرع `main`.

## المترجم والملخّص (ترجمة الملازم وتلخيصها)

قسم بالتطبيق يرفع بيه الطالب ملزمة (PDF، صور، Word، PowerPoint، أو نص ملصوق) و:
- **يترجمها** للعربي (مع المصطلح الإنكليزي بين قوسين) أو للإنكليزي، صفحة بصفحة وبنفس الترتيب والجداول.
- أو **يلخّصها ويطلّع أسئلة**: الخلاصة والنقاط المهمة، المصطلحات، اختيار من متعدد، صح وخطأ، عدّد، علّل، قارن، املأ الفراغ، أسئلة مقالية — بثلاث مستويات (مختصر/متوسط/شامل) وبالعربي أو الإنكليزي أو الاثنين.
- كل نقطة وسؤال عليه رقم الصفحة حتى الطالب يراجعه بالملزمة. الأسئلة تفاعلية، ويكدر ينسخ أو ينزّل أو يطبع (PDF).

الذكاء الاصطناعي هو **Gemini Flash** (`gemini-3.8-flash`، وبعده `3.7` و `3.6` و `3.5` كبدائل) من Google AI Studio بالخطة **المجانية**. المتصفح يقسّم الملف لأجزاء ويدزها لدالة `study-ai` **جزء واحد بنفس الوقت**، والدالة تدز كل جزء لـ Gemini وترجع النتيجة أول بأول. الملف ما ينحفظ بخادم القسم، والنتائج تنحفظ على جهاز الطالب بس (لكل حساب لحاله).

### التفعيل

1. سوّي مفتاح مجاني من [aistudio.google.com/apikey](https://aistudio.google.com/apikey) (ما يحتاج بطاقة).
2. بـ Supabase: **Edge Functions → Secrets** أضف `GEMINI_API_KEY`.
3. انشر الدالة: `supabase functions deploy study-ai --no-verify-jwt` (الدالة نفسها تتأكد من جلسة الطالب وإن حسابه فعّال).
4. ابنِ الموقع وانشره مثل العادة.

### الحدود

الخطة المجانية مشتركة للمشروع كله (مو لكل طالب) ومحسوبة **لكل موديل لحاله**. Google ما تكتب الأرقام بالتوثيق، تطلع بصفحة [Rate limits بـ AI Studio](https://aistudio.google.com/rate-limit). بالفحص الحقيقي (1 تشرين الأول 2026) Google رجّعت لـ `gemini-3.8-flash`: **20 طلب باليوم** للمشروع كله (`GenerateRequestsPerDayPerProjectPerModel-FreeTier`، limit: 20)، والطلبات اللي فشلت بـ 503 انحسبت منها. الحد اليومي يتصفّر بمنتصف الليل بتوقيت كاليفورنيا (حوالي 10–11 الصبح بتوقيت بغداد).

- لهذا الدالة تجرّب 4 موديلات Flash بالترتيب (`3.8` ← `3.7` ← `3.6` ← `3.5`)، كل واحد إله حصته. إذا موديل مشغول (503) أو علگ أو خلصت حصته اليوم أو فشل وهو بعده يفكر، نفس الجزء يروح للي بعده فوراً. يعني القسم يحصل تقريباً 80 طلب باليوم بالمجان بدل 20.
- كل طالب **20 جزء باليوم**، والقسم كله **800 جزء باليوم** (مثل ما طلبت). عملياً حد Google أقل من حد القسم، فلما يخلص تطلع الرسالة الواضحة بالعربي.
- القسم كله **10 أجزاء بالدقيقة**. إذا انشغلت الدقيقة، أو كل الموديلات مشغولة، التطبيق يوقف شوية (يطلع للطالب «نكمل بعد … ثانية») ويرجع يحاول تلقائياً (6 مرات بالأكثر لكل جزء، لأن كل محاولة فاشلة تنحسب من حصة Google).
- وقت الضغط ممكن الطلب يعلگ بطابور Google بدون جواب ولا خطأ. إذا الموديل ما بدأ يجاوب خلال 40 ثانية، الدالة تتركه وتسأل اللي بعده بالوقت الباقي. وإذا ولا واحد جاوب، التطبيق يعيد المحاولة بعد 30 ثانية (ما يقسّم الجزء، لأن المشكلة مو بطوله).
- إذا تحتاج أكثر من هذا: فعّل الفوترة بمشروع Google (Tier 1). Flash رخيص، بس هذا قرارك.
- إذا خلص حد الطالب أو القسم أو حصة Gemini اليومية، تطلع رسالة واضحة بالعربي ويوقف الطلب.
- الجزء = 4 صفحات للترجمة، و5–12 صفحة للتلخيص حسب المستوى. يعني ملزمة 40 صفحة تحتاج تقريباً 10 أجزاء ترجمة، أو 5 أجزاء مراجعة سريعة. الطلب اللي يحتاج أكثر من 20 جزء ما يبدي، ويطلب من الطالب يختار صفحات أقل.
- الجزء ينحسب من حصة الطالب بس لما Gemini يبدأ يجاوب فعلاً. يعني إعادة المحاولة بسبب الزحمة (503 أو 429 أو ما ردّ) ما تاكل من الـ 20 جزء. الجزء اللي ينقسم لأنه طويل، كل نص منه ينحسب جزء.
- حتى ما تخلص حصة القسم بإعادة المحاولات، كل طالب عنده **60 محاولة باليوم** (مع الإعادات). وحد القسم (800) ينحسب على كل محاولة توصل لـ Gemini، لأن Google تحسب الطلبات مو الأجزاء.

### إعدادات اختيارية (Secrets بنفس المكان)

| الاسم | الافتراضي | شنو يسوي |
|---|---|---|
| `AI_MODEL` | `gemini-3.8-flash` | اسم الموديل (من [قائمة الموديلات](https://ai.google.dev/gemini-api/docs/models)) |
| `AI_FALLBACK_MODELS` | `gemini-3.7-flash,gemini-3.6-flash,gemini-3.5-flash` | الموديلات البديلة بالترتيب (مفصولة بفاصلة). كل واحد إله حصة مجانية لحاله. تكدر تضيف `gemini-3.5-flash-lite` بالآخر إذا تريد حصة أكثر بجودة أقل. `off` = الموديل الأساسي بس |
| `AI_USER_DAILY` | `20` | أجزاء كل طالب خلال 24 ساعة. إذا غيّرته، غيّر `MAX_PARTS` بـ `web/src/sb/study/run.js` |
| `AI_USER_TRIES` | `60` | محاولات كل طالب خلال 24 ساعة، مع الإعادات بسبب الزحمة |
| `AI_GLOBAL_DAILY` | `800` | أجزاء القسم كله خلال 24 ساعة |
| `AI_GLOBAL_RPM` | `10` | أجزاء القسم كله بالدقيقة |
| `AI_FIRST_BYTE_SEC` | `40` | كم ثانية ننتظر الموديل يبدأ يجاوب قبل ما نحوّل للي بعده |
| `AI_TIME_LIMIT_SEC` | `135` | أقصى وقت لكل جزء. بالخطة المجانية لـ Supabase خليه 135، بالخطط المدفوعة ممكن لحد 380 |

### الخصوصية

بالخطة المجانية Google تكدر تستخدم المحتوى المرسل لتحسين خدماتها (مكتوب بـ [صفحة الأسعار](https://ai.google.dev/gemini-api/docs/pricing)). لهذا القسم يكتب للطالب ما يرفع ملفات بيها معلومات شخصية. إذا تريد هذا ما يصير، فعّل الفوترة بمشروع Google (الخطة المدفوعة ما تستخدم البيانات).

### فحص الدالة

```bash
deno test --allow-net --allow-env --allow-run --allow-read supabase/functions/tests/study-ai-test.ts
```
يشغّل الدالة الحقيقية على Supabase و Gemini وهميين (ما يحتاج مفاتيح ولا إنترنت). سجلات الدالة (Edge Functions → study-ai → Logs) تبيّن الموديل وعدد التوكنات وسبب الانتهاء لكل جزء.

## إذا تريد تنقله لمشروع Supabase جديد

1. سوّي مشروع جديد بـ Supabase.
2. افتح SQL Editor، الصق `supabase/schema.sql`، وغيّر القيم بقسم «Initial data» بآخره (رمز القسم، إيميل المرسل، رابط التطبيق) قبل التشغيل.
3. انشر الدوال: `supabase functions deploy register reset-pin mail-status study-ai --no-verify-jwt`.
4. حط مفتاح Brevo إما بجدول `private.config` أو كـ secret باسم `BREVO_API_KEY`.
5. غيّر `SUPABASE_URL` و `SUPABASE_KEY` بملف `web/src/sb/config.js` لقيم المشروع الجديد، وابنِ الموقع من جديد.

أول حساب يتسجل بالمشروع الجديد يصير هو المالك.
